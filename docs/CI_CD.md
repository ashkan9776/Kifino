# راهنمای جامع معماری CI/CD کیفینو (Kifino)

این مستند تشریح‌کننده جریان‌های کاری اتوماتیک (GitHub Actions Workflows) پروژه کیفینو برای اعتبارسنجی مداوم کیفیت کد (CI) و انتشار خودکار نسخه‌های اندروید و ویندوز (CD) می‌باشد.

---

## ۱. نقشه جریان‌های کاری (Workflows)

پروژه دارای ۳ جریان کاری استاندارد در مسیر `.github/workflows/` است:

```
.github/
└── workflows/
    ├── ci.yml                 # اعتبارسنجی کیفیت کد، فرمت، تحلیل و بیلد تستی
    ├── release.yml            # ساخت پکیج‌های نهایی اندروید، ویندوز و انتشار در GitHub Releases
    └── scheduled_health.yml   # مانیتورینگ دوره‌ای پکیج‌ها و سلامت مخزن
```

---

## ۲. جریان کاری Continuous Integration (`ci.yml`)

### زمان اجرا:
- با هر `push` به شاخه‌های `main`, `master`, `dev`, `release/*`
- با هر `pull_request` به شاخه‌های اصلی

### مراحل اجرا:
1. **کنترل هم‌زمانی (Concurrency Control):** کنسل کردن خودکار اجراهای قدیمی‌تر روی یک Branch برای صرفه‌جویی در منابع.
2. **بررسی کیفیت کد و تست‌ها (`quality_and_tests`):**
   - نصب جاوا ۱۷ و فلاتر استیبل با کش هوشمند پکیج‌ها (`pub-cache` و `gradle`).
   - بررسی دقیق فرمت‌بندی کد (`dart format --output=none --set-exit-if-changed .`).
   - تحلیل استاتیک سخت‌گیرانه (`flutter analyze --fatal-infos --fatal-warnings`).
   - اجرای تمام ۲۳۹ تست واحد و ویجت و ذخیره گزارش پوشش تست (`coverage/lcov.info`).
3. **تست بیلد اندروید (`build_android_check`):**
   - کامپایل تست دیباگ اندروید برای اطمینان از سلامت کدهای Gradle و وابستگی‌های نیتیو.
4. **تست بیلد ویندوز (`build_windows_check`):**
   - کامپایل نیتیو روی ماشین ویندوزی (`windows-latest`) با CMake برای اطمینان از سلامت کدهای C++ و Win32 Runner.

---

## ۳. جریان کاری Continuous Delivery و انتشار (`release.yml`)

### نحوه اجرا:
1. **اتوماتیک با تگ گیت:**
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```
2. **دستی از طریق پنل گیت‌هاب (Workflow Dispatch):**
   - به تب **Actions** در گیت‌هاب بروید.
   - جریان **Kifino Release** را انتخاب کرده و دکمه **Run workflow** را بزنید.
   - می‌توانید تگ نسخه (مثلاً `v1.0.0`)، حالت Pre-release یا Draft و یادداشت‌های دلخواه را وارد کنید.

### محصولات خروجی (Artifacts):
این پایپ‌لاین به‌صورت خودکار فایل‌های زیر را تولید کرده، هش SHA-256 آن‌ها را محاسبه کرده و در GitHub Release پیوست می‌کند:

| نام فایل | پلتفرم | توضیحات |
| :--- | :--- | :--- |
| `Kifino-Android-Universal.apk` | اندروید | نسخه جامع برای تمام گوشی‌های اندرویدی |
| `Kifino-Android-arm64-v8a.apk` | اندروید | نسخه سبک و پرسرعت برای گوشی‌های ۶۴ بیتی مدرن |
| `Kifino-Android-armeabi-v7a.apk` | اندروید | نسخه سازگار با گوشی‌های ۳۲ بیتی قدیمی‌تر |
| `Kifino-Android-x86_64.apk` | اندروید | نسخه شبیه‌سازها و کروم‌بوک‌های اینتل/AMD |
| `Kifino-Android.aab` | اندروید | بسته رسمی گوگل‌پلی و کافه بازار/مایکت |
| `Kifino-Windows-x64.zip` | ویندوز | نسخه پرتابل آماده اجرای ویندوز ۱۰ و ۱۱ |
| `checksums.txt` | تمام پلتفرم‌ها | لیست کدهای هش SHA-256 تمامی فایل‌ها جهت امنیت |

## ۴. نحوه تنظیم امضای دیجیتال اندروید در گیت‌هاب (Signing Secrets)

اگر تمایل دارید خروجی APK و AAB به جای امضای پیش‌فرض با کلید اختصاصی و ریلیز شما امضا شوند:

۱. فایل Keystore خود (`.jks`) را به فرمت Base64 تبدیل کنید:
   ```bash
   base64 -w 0 my-release-key.jks > keystore_base64.txt
   ```
۲. در مخزن گیت‌هاب به مسیر **Settings** > **Secrets and variables** > **Actions** بروید.
۳. متغیرهای زیر را در بخش **Repository secrets** تعریف کنید:
   - `KEYSTORE_BASE64`: محتوای متنی فایل `keystore_base64.txt`
   - `KEY_ALIAS`: نام الیاس کلید (مثلاً `kifino-key`)
   - `KEY_PASSWORD`: رمز عبور کلید
   - `STORE_PASSWORD`: رمز عبور فایل کی‌استور

> **نکته:** در صورتی که این متغیرها تعریف نشده باشند، پایپ‌لاین به طور خودکار از کلید توسعه استفاده کرده و بیلد بدون خطا به پایان می‌رسد.
